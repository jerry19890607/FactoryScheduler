技術說明：資料流與排程演算法

一句話：把各來源訂單翻成機台需求 → 算交期 → 抽件優先拆出 → 在時間軸貪婪指派到最快做完的合格機台，並避開停機時段。

一輸入資料（三類）

1. 主檔 Factory_Scheduling_Schema_V4_3.2.xlsx（--master）

「不常變」的基礎資料，一個 Excel 內含 5 個分頁：

分頁內容用途
Machine_Info15 台機台：各群組 UPH（Wave / ECC / IPass / ICASH 片/小時）、模組 1~9、製程階段機台能做什麼、速率多少
Machine_Calendar機台排空時段（例 MX_1 在 11/10 09:00–11:00 停機）排程要「挖空」的時間
Customer_Deadline客戶別名（CTBC｜CTCTW）、開始時間 8:30、抽件前置 3 分、各級抽件截止、SLA Std、SLA_REF 規則算交期用
Product_Master102 筆：(客戶, 產品代號) → 替代版面轉譯第一步
Product_Setup102 筆：(客戶, 替代版面) → 產品群組 ＋ 必備模組轉譯第二步

2. 日常訂單（--orders，可多檔）

一天的工單，兩種來源：

  • Legacy：舊系統，.xls 或 .txt（以 | 分隔）
  • APS：新系統，.xlsx（資料常在非第一分頁，程式會自動掃描）

每一列 = 一個訂單行（一張工單＋一個產品），關鍵欄位： CUSTOMER_NAME、WORKORDER_ID、PACKAGE_ID、PRODUCT_REF、QTY、 ARRIVER_DATE(到檔)、PROMISE_DATE(承諾)、SLA_REF、SLA。

目前實跑：Legacy 87 包 ＋ APS 4 包。

3. 抽件 Pull（--pulls，可多檔）

「把某張工單的某些卡片提前優先做」的指令。Legacy 文字檔、APS .xls。 欄位：WORKORDER_ID、PACKAGE_ID、PULL_TYPE(EMER_1 / EMER_2 / Std)、PULL_TIME、STATUS。

二輸出資料 排程結果_介面format.xlsx（--out）

每台機台一張分頁，欄位對齊「介面 format.xlsx」：

選擇 / 優先順序 / CUSTOMER_NAME / WORKORDER_ID / PACKAGE_ID / PACKAGE_ID Qty / PULL EMER_1 Qty / PULL EMER_2 Qty / PULL Std Qty / ARRIVER_DATE / PROMISE_DATE / 開始日期時間 / 結束日期時間 / Total time (Min)

每一列 = 一個排程任務：

  • 優先順序 = 在該機台的第幾個做
  • PACKAGE_ID Qty = 一般任務的片數；若是抽件批，片數改放到對應的 PULL EMER_1/2/Std Qty 欄並上色
  • 開始 / 結束日期時間 = 算出的實際時鐘時間（已避開停機時段）
  • Total time (Min) = setup ＋ 加工分鐘
  • 外加一張 摘要頁：排程起點、makespan、逾期數、未分配數

三運算邏輯（四段轉譯 → 交期 → 抽件 → 排程）

步驟 1：四段轉譯（把「訂單」翻成「機台能懂的需求」）

1
客戶別名 → 標準客戶名（CTCTW → CTBC）
2
(客戶, 產品代號) → 替代版面（Product_Master）
3
(客戶, 替代版面) → 產品群組 ＋ 必備模組（Product_Setup）
4
必備模組 → 哪些機台「做得到」（模組涵蓋 ＋ 該群組 UPH>0）

步驟 2：交期規則

  • 最早開始 = 到檔日 ARRIVER_DATE ＋ 客戶「Start Time」(8:30)
  • 最晚完成 = 承諾日 PROMISE_DATE ＋（SLA_REF 代碼命中的時間，否則 SLA Std，否則 23:59）

步驟 3：抽件（單一筆抽件模型）

  • 每一筆抽件 = 單一張卡（並非整筆工單 / 整包），歸到所屬整包（先比 PACKAGE_ID，再比 WORKORDER_ID 所屬包）。
  • 整包仍為一個不可拆分任務；抽件只是把整包變急：累計各等級數量（EMER_1 / EMER_2 / Std）、標為優先、交期收緊為最緊等級時間、加客戶 Pull_Setup_Min 前置。
  • 介面以整包一列呈現，各等級抽件數量放到對應欄並標色。
  • 去重：抽件檔會持續疊加，以 ID ＋ FILE_NAME 為鍵，已匯入過者略過。

步驟 4：時間軸排程（貪婪，時間前推）

# 時間前推的貪婪清單排程，同時決定「指派機台」與「時鐘時間」
排序：  抽件/優先 → 交期(EDD) → 數量大者先
指派：  每個任務選「完工時間最早」的合格機台
        （已考慮機台目前可用時間、最早開始、Machine_Calendar 挖空、抽件 setup）
凍結：  狀態為處理中/已完成或已釘選者先固定排在該機台
  • 排序：抽件 / 優先 → 交期最緊（EDD）→ 數量大的先
  • 凍結：已開工 / 已完成 / Leader 鎖定的任務先固定在原機台
  • 指派：每個任務挑「做完最早」的合格機台，加工時間 = 片數 ÷ 該群組 UPH，遇到機台停機時段會自動跳過順延
  • 指標：目前 makespan 158.3 分、逾期 17、未分配 0
一句話總結：把各來源訂單翻成機台需求 → 算出每張工單的最早能開工 / 最晚要完成 → 抽件優先拆出來 → 在時間軸上貪婪地把每個任務塞進最快做完、且做得到的機台，同時避開停機時段。
