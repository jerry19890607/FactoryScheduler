訂單行:日常訂單檔的一列,即一個工單加一個產品,是排程的基本單位
標準客戶名:Customer_Deadline 的 CUSTOMER_NAME 別名清單的第一個(例:CTBC)
最早開始:訂單可以開始製卡的時間
最晚完成:訂單必須完成的時間
抽件:把指定的卡片提前、優先製作
抽件事件:一張工單加上一個抽件檔(實體檔案)
抽件批:抽件事件產生的作業,有自己的交期與前置時間
剩餘批:抽件後工單剩下的張數,保留原交期
任務:排程的單位:一般任務、抽件批、剩餘批
凍結:重排時不可更動的任務(已開工,完成或 Leader 鎖定)


處理流程
日常:  檔案出現 → 等檔案穩定 → 讀取 → 正規化 → 規則計算 → 排程 → 驗證 → 發佈
抽件:  檔案出現 → 等檔案穩定 → 讀取 → 比對訂單 → 套用抽件規則 → 鎖定已開工與 Leader 調整
       → 限時重排 → 驗證 → 發佈新版本 → 寫 Pull_Log

4.4 Customer_Deadline
欄位(標題開頭):型別:規則
CUSTOMER_NAME:文字:別名清單,以直線符號分隔,第一個是標準名稱
Start Time:時間:客戶可開始製卡的時間,例 8:30
Pull_Setup_Min:整數(分):抽件需要時間,可能是文字(例 '3'),需解析
PULL EMER_1:時間:抽件等級 1 的結束時間
PULL EMER_2:時間:抽件等級 2 的結束時間
PULL Std:時間:抽件標準結束時間
SLA Std:時間:一般訂單的標準結束時間
SLA_REF:文字:代碼與結束時間清單,見下方語法


CUSTOMER_NAME 範例:  CTBC|CTCTW
SLA_REF 範例:        3D=11:00|D00=11:00
語法:   清單 = 項目 { | 項目 }     項目 = 代碼 = 時間(H:mm 或 HH:mm)
• 別名比對:去除空白、不分大小寫,也接受全形直線與等號。同一別名出現在兩列為錯誤。
• 時間欄位可能是文字或真正的時間值,兩者都要支援。
• SLA_REF 代碼不分大小寫,必須完整相等(D0 不等於 D00)。
• PULL_TIME 的值直接對應標題:PULL EMER_1、PULL EMER_2、PULL Std。


4.5 Product_Master(訂單轉譯主檔)
欄位(標題開頭):型別:規則
CUSTOMER_NAME:文字:標準客戶名
產品代號:文字:必須以文字讀取,保留前導 0(例 040000322)。部分儲存格是數字型別,轉成文字時不可出現科學記號或小數
產品描述:文字僅顯示
替代版面:實際用的產品

Product_Setup (生產途程主檔)

產品群組:文字:例 ECC、IPASS、ICASH;空白 = 無群組。用於相近產品排在一起,
必備模組1 至 9:文字機台必須具備;空白略過;同一產品重複的模組只算一次
這張表的作用是：定義機台模組。注意！這裡的主鍵(Key) 必須是表一的 實際生產/替代版面。
只要卡片的物理製程一樣（都過 DUG），在這邊就只要建一筆資料，不用因為訂單代號不同而重複建檔。
