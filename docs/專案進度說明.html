1需求理解

目標：把每天來自不同系統的工單，自動分配到「做得到且最快做完」的機台，產生每台機台的作業時序表。只排製程 1（機台）。

三類輸入

  • 主檔：機台能力、客戶交期規則、產品轉譯、機台排空行事曆。
  • 日常訂單：Legacy（舊系統 .xls / .txt）、APS（新系統 .xlsx）。
  • 抽件（Pull）：把指定卡片提前、優先製作，分 EMER_1 / EMER_2 / Std 三個急迫等級。

核心規則

  • 一張工單（PACKAGE_ID）為不可分割的基本任務。
  • 四段轉譯：客戶別名 → 產品代號 → 替代版面 → 產品群組 / 必備模組 → 合格機台。
  • 交期：最早開始 =（到檔日 ＋ 客戶開始時間）；最晚完成 =（承諾日 ＋ SLA 規則）。
  • 抽件拆成「抽件批（提前優先）」與「剩餘批（保留原交期）」。
  • 已開工 / 已完成 / Leader 鎖定的任務「凍結」，重排時不可更動。
  • 機台有排空時段（Machine_Calendar），排程要避開。

使用角色

  • Leader：調整排程結果、歷史查詢。
  • OP：掃 barcode 多選、整包更新為完成。

  • 部署目標：Windows 封閉網路，交付為可執行檔，含使用者介面。

3排程邏輯

把各來源訂單翻成機台需求 → 算出每張工單的「最早能開工 / 最晚要完成」 → 抽件優先拆出來 → 在時間軸上，逐一把每個任務塞進「做得到且做完最早」的機台，並自動避開停機時段。
  • 排序優先序：抽件 / 優先 → 交期最緊（EDD）→ 片數大的先。
  • 加工時間 = 片數 ÷ 該產品群組在該機台的 UPH（片 / 小時）。
  • 凍結任務先固定於原機台，其餘才做指派。
